# 🗑 Deleted Message Notifier — Telegram Business Bot

Мультипользовательский бизнес-бот Telegram, который сообщает владельцу аккаунта об удалении
сообщения в его личных чатах: кто автор (@тег + ID), в каком чате, когда сообщение было
отправлено и удалено, и **какой у него был текст**. Монетизация — Telegram Stars (XTR).

## 🔒 Приватность и ответственность

- Бот работает **только в чатах аккаунта, который сам его подключил** (Telegram Business → Чат-боты),
  и только в тех чатах, к которым владелец дал доступ.
- Telegram в событии `deleted_business_messages` присылает **только номера** удалённых сообщений.
  Поэтому бот сохраняет текст/подпись (с форматированием) и **скачивает медиафайлы на диск** в момент
  получения (`business_message`, правки — `edited_business_message`) и показывает их при удалении.
  Текст отключается `STORE_MESSAGE_TEXT=0`, скачивание медиа — `STORE_MEDIA=0`.
- Данные хранятся **локально** (база + папка `data/media/`) и никуда не передаются.
  Одноразовые (view-once) медиа Telegram ботам не отдаёт вовсе — их сохранить нельзя.
- Данные **НЕ удаляются** при отключении бизнес-подключения или окончании подписки; при повторном
  подключении состояние восстанавливается. Автоудаление по сроку — только если `RETENTION_DAYS > 0`
  (по умолчанию `0` — хранить бессрочно). Без активной подписки новые записи не пишутся.
- **Ответственность за использование бота лежит на пользователе.** Соблюдайте законы своей страны
  и правила Telegram.

## 🏗 Архитектура

```
Telegram ──long polling──► Dispatcher
                              │  outer-middleware UserMiddleware (message / callback / pre_checkout):
                              │  регистрирует юзера в users, подставляет lang
                              ▼
   handlers/admin.py     /stats /users /grant /extend /revoke /subinfo /payments /refund /backup
   handlers/history.py   «История»: свои записи, поиск, фильтр по дате, пагинация (изоляция)
   handlers/start.py     /start, выбор языка, онбординг + триал
   handlers/menu.py      inline-меню: статус, подписка, подключение, настройки (язык/помощь)
   handlers/payments.py  тарифы → send_invoice(XTR) → pre_checkout → successful_payment, возвраты
   handlers/business.py  business_connection → connections
                         business_message → messages (метаданные, текст, media_path)
                         edited_business_message → message_edits (история «Было/Стало») + уведомление
                         deleted_business_messages → уведомление владельцу (+ тег бота как водяной знак)
                              │
                              ▼
                     db.py (aiosqlite, SQLite WAL)  ◄── tasks.py (каждые 10 мин:
                                                         истечение подписок + напоминания,
                                                         очистка старых метаданных)
```

Изоляция пользователей: каждое бизнес-событие несёт `business_connection_id`, по нему из
`connections` берётся `owner_user_id`; все чтения/записи `messages` фильтруются по
`owner_user_id`, а уведомление уходит только этому владельцу.

### Схема БД (связи по `owner_user_id`)

| Таблица | Поля | Назначение |
|---|---|---|
| `users` | `user_id` PK, `username`, `first_name`, `language`, `notifications_enabled`, `trial_used`, `created_at`, `updated_at` | владельцы, язык (ru/en) |
| `subscriptions` | `owner_user_id` PK→users, `plan` (trial/m1/m3/y1/grant), `expires_at` (NULL = бессрочно), `is_active`, `last_reminder_at`, `updated_at` | подписка 1:1 |
| `connections` | `business_connection_id` PK, `owner_user_id`→users, `user_chat_id`, `is_enabled`, `can_reply`, `created_at`, `updated_at` | бизнес-подключения N:1 |
| `messages` | `id` PK, `owner_user_id`→users, `business_connection_id`, `chat_id`, `message_id`, `from_user_id`, `from_username`, `from_name`, `content_type`, `text`, `file_id`, `media_path`, `media_size`, `is_deleted`, `deleted_at`, `sent_at`, `saved_at`; UNIQUE(`owner_user_id`,`chat_id`,`message_id`); индекс `(owner_user_id, sent_at)` | метаданные, текст/подпись, `file_id` (ссылка Telegram) и `media_path` (скачанный файл на диске) + `media_size` для проверки целостности; `is_deleted`/`deleted_at` — статус удаления |
| `message_edits` | `id` PK, `owner_user_id`→users, `chat_id`, `message_id`, `old_text`, `new_text`, `edited_at` | полная история правок (каждая правка = строка «старое → новое») |
| `payments` | `id` PK, `owner_user_id`→users, `plan`, `amount`, `currency`, `telegram_payment_charge_id` UNIQUE, `status` (paid/refunded), `created_at`, `refunded_at` | история оплат, нужна для возвратов |

## 🚀 Запуск

### 1. Создать бота в @BotFather
1. `/newbot` → имя и username → скопируйте **токен**.
2. **Business Mode:** `/mybots` → ваш бот → **Bot Settings** → **Business Mode** → **Turn on**.
   Без этого Telegram не даст подключить бота к аккаунту и не пришлёт бизнес-события.
3. (Желательно) `/setdescription` — кратко опишите, что бот сообщает только факт удаления.

### 2. Приём Telegram Stars
Для цифровых товаров в Telegram используются **только звёзды** — платёжный провайдер подключать
**не нужно**: счёт с `currency="XTR"` работает сразу, `provider_token` не передаётся.
- Полученные звёзды видны в боте: @BotFather → ваш бот → **Bot Settings → Payments / Balance**
  (или в приложении Telegram: профиль бота → Stars). Вывод — через Fragment после периода удержания.
- Telegram требует от бота поддержку по платежам — она есть: команда `/paysupport`.
- Возврат: администратор вызывает `/payments [user_id]`, берёт `telegram_payment_charge_id`
  и выполняет `/refund <charge_id>` — бот вызывает `refundStarPayment`, отмечает платёж и откатывает срок.
  Если возврат пришёл извне (событие `refunded_payment`), БД синхронизируется автоматически.

### 3. Установка
```bash
cd deleted_notify_bot
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # Windows: copy .env.example .env
```
Заполните в `.env` как минимум `BOT_TOKEN` и `ADMIN_ID` (свой ID можно узнать у @userinfobot).
Цены тарифов — `PRICE_30D`, `PRICE_90D`, `PRICE_365D` (в звёздах), пробный период — `TRIAL_DAYS` (по умолчанию 7).
Дополнительные администраторы — `ADMIN_IDS` (через запятую).

### Тарифы (по умолчанию)

| Тариф | Срок | Цена | ≈ за 30 дней | Выгода |
|---|---|---|---|---|
| 30 дней | 30 дн | **200 ⭐** | 200 ⭐ | — |
| 90 дней | 90 дн | **500 ⭐** | ≈167 ⭐ | −17 % |
| 1 год | 365 дн | **1600 ⭐** | ≈133 ⭐ | −33 % |

Цены меняются в `.env` без правки кода. Тариф «Навсегда» удалён.

### 4. Запуск
```bash
python main.py
```
В логе должно появиться `Бот @… запускается` без предупреждения про Business Mode.
Бот запускает polling с явным списком обновлений (по умолчанию бизнес-события не приходят):
```python
allowed_updates = ["message", "callback_query", "pre_checkout_query",
                   "business_connection", "business_message", "edited_business_message",
                   "deleted_business_messages"]
```

### 5. Подключение пользователем
1. Пользователь пишет боту `/start` → выбирает язык → получает приветствие, предупреждение о
   приватности и пробный период.
2. Telegram → **Настройки → Telegram для бизнеса → Чат-боты** → вводит @username бота → выбирает
   чаты (нужен **Telegram Premium**).
3. Бот присылает «🔗 Бот подключён». С этого момента удаления сообщений в выбранных чатах
   приходят уведомлениями.

## 🛠 Админ-команды (только `ADMIN_ID` и `ADMIN_IDS`)
| Команда | Действие |
|---|---|
| `/stats` | пользователи, активные/платные подписки, подключения, звёзды |
| `/users [N]` | последние N пользователей и их подписки |
| `/grant <id> <дней\|forever>` | выдать подписку (`forever` — бессрочно) |
| `/extend <id> <дней\|forever>` | продлить подписку (дни добавляются к текущему сроку) |
| `/revoke <id>` | досрочно отозвать подписку |
| `/subinfo <id>` | подписка + подключение + число записей пользователя |
| `/payments [id]` | последние платежи с `charge_id` |
| `/refund <charge_id>` | возврат звёзд (refundStarPayment) |
| `/backup` | резервная копия базы (файл в `data/backups/` + присылается в чат) |

Доступ проверяется на сервере (фильтр `IsAdmin`), а не скрытием кнопок. Админ-раздел
даёт **операционные** данные (счётчики, статусы, суммы) — он не открывает содержимое
чужих переписок.

## 🕓 Раздел «История» (для пользователя)
Кнопка «❒ История» в меню — просмотр **своих** сохранённых записей: постранично,
поиск по тексту, фильтры (все / 7 дней / 30 дней / только удалённые), открытие записи
с пересылкой сохранённого медиа. Данные строго изолированы по `owner_user_id`.

## 💾 Резервное копирование и восстановление
- Копия: команда `/backup` — делает согласованный снимок базы (`VACUUM INTO`) **и упаковывает его
  вместе с папкой медиа** в `data/backups/backup-ГГГГММДД-ЧЧММСС.zip` (внутри: `bot.db` + `media/…`),
  затем присылает архив в чат (если он меньше ~45 МБ; иначе остаётся только на диске).
- Где лежат данные: база — `DB_PATH` (по умолчанию `data/bot.db`), медиафайлы — `MEDIA_DIR`
  (по умолчанию `data/media/`), копии — `data/backups/`.
- Восстановление: остановите бота (Ctrl+C), распакуйте архив, положите `bot.db` на место `data/bot.db`
  (удалив `bot.db-wal`/`bot.db-shm` при наличии) и папку `media/` — в `data/media/`, запустите снова.
  Пути к файлам хранятся относительными, поэтому связи «сообщение ↔ файл» сохраняются.
- Папки `data/` и `.env` исключены из Git (`.gitignore`).

## 🗄 Перенос на сервер / PostgreSQL (на будущее)
- Весь доступ к данным собран в `db.py` (класс `Database`) — бизнес-логика к SQLite напрямую
  не обращается, поэтому слой заменяется без правок хендлеров.
- Пути относительные (`DB_PATH`), жёсткой привязки к папкам компьютера нет.
- Перенос на свой сервер: скопируйте проект и файл `data/bot.db`, задайте `.env`, запустите.
- Переход на PostgreSQL: заменить реализацию `Database` на драйвер `asyncpg`/SQLAlchemy,
  перенести строки таблиц (схема и связи по `owner_user_id` те же). SQL в проекте простой
  и переносимый; специфичен для SQLite только `VACUUM INTO` в `/backup`.

## ℹ️ Ограничения Telegram (их нельзя обойти кодом)
- Отслеживаются только сообщения, пришедшие **после** подключения (и при активной подписке) —
  для более старых придёт «детали отправителя недоступны».
- Событие удаления содержит **только номера** сообщений (`business_connection_id`, `chat`,
  `message_ids`) — ни текста, ни автора, ни времени. Поэтому всё нужное сохраняется заранее,
  в момент получения сообщения.
- Telegram не сообщает, **кто** удалил сообщение и **когда** именно; показываются автор сообщения
  и время получения события. Если владелец сам удалит сообщение собеседника, уведомление тоже придёт.
- **Одноразовые (view-once) медиа ботам не передаются вообще** — показать их невозможно
  ни при каких настройках кода.
- Редактирование отслеживается для текста и подписей к медиа (приходит событие `edited_business_message`).
  Каждая правка показывается как «Было / Стало» и сохраняется в историю; дубликаты событий отсекаются.
- Медиа скачивается на диск сразу при получении и показывается из локальной копии; если файла нет
  (скачать не удалось), бот пробует `file_id`, а если и он недоступен — честно сообщает об этом.
- Свои сообщения владельца в уведомления не попадают.
- Бизнес-боты не получают события из секретных чатов, групп и каналов.
